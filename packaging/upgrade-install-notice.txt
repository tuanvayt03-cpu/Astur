ASTUR VI UPDATE 2.4.0.15 (PREVIEW)

This installer UPDATES your existing Astur installation IN PLACE.
It is an experimental community fork, NOT an official stable upstream release.

BEFORE INSTALLING
- Quit the running Astur window manager. Do not run two managers together.
- The installer retains the original AppId and installation directory.
- Your existing settings and workspace configuration are preserved.
- When prompted, allow the current app to close. Auto-restart is disabled.
- The installer is UNSIGNED. Verify its SHA256 and source. Do not disable
  Windows Defender or SmartScreen to launch an untrusted executable.

ROLLBACK
Before touching the installed files, the installer saves the existing
Astur.exe, astur-settings.exe, astur.conf and navbar.conf (when available).
First original snapshot:
%LOCALAPPDATA%\Astur\UpgradeBackup\before-vi-update-2.4.0.1
Immediately previous installation:
%LOCALAPPDATA%\Astur\UpgradeBackup\before-vi-update-2.4.0.15
These snapshots are never overwritten on a repeat update.
To roll back: quit Astur, restore the saved binaries/config, or reinstall
the previously used installer. Keep the other manager stopped.

NEW IN 2.4.0.15
- Opened windows first use an empty visible slot. If slots are full, a new
  window occupies the previously used OTHER slot as a tab (layer N-1),
  leaving the actively focused window anchored in its present slot.
  Prior windows remain managed; none is automatically closed or minimized.
- New: minimized windows reserve their scrolling slot, so minimizing CS1
  does not relocate CS2 into CS1. Restoring a window returns it to its slot.
- New: window admissions and delayed focus events preserve the actively
  used slot; new windows use a free or non-anchor visible tab as intended.
- New: Alt+left-drag or native title-bar drag can exchange occupied slots
  even when a slot contains multiple tabs. Drop targeting uses Astur's
  stable layout geometry; left/right/below drop zones still work.
- New: nearly-visible half-width columns no longer jump/recenter on focus
  solely because the outermost pixels are clipped.
- Dragging a normal resizable app to the physical top edge of its monitor
  maximizes it using native Windows behavior. A click without movement,
  edge resize and native F11 are not reinterpreted as a drag-maximize.
- Retains Window Policy Engine v1, background spawn protection, Zalo
  notification exclusions, and previous multi-display fixes.

ACCEPTANCE LIMITATIONS
The code and installer are tested on isolated Windows CI. The real
1-monitor and 2-monitor desktop (including 1/2, 1/4 and 1/5 layouts,
native maximized/F11 windows, MT5 and Zalo popups) still requires
manual acceptance. A CI pass is not a claim that live UI is verified.
